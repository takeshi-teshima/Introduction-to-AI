# Audio Script 処理ガイドライン

## 背景
元の講義スクリプト（`1_Scripts/*.txt`）を TTS 用の Audio Script（`3_Audio_Scripts/*.smd`）に変換する際の判断基準を定める。

## 核心的な問題
元のスクリプトは **口語で講義する前提** で書かれており、文語では冗長に見える表現にも教育的な意図がある。
処理時にこれらを「洗練」と称して削ると、以下の価値が失われる：

### 削ってはいけないもの（＝口語の教育的価値）

1. **段階的な説明の積み上げ**
   - 「まず〜します。そうすると〜になります。つまり〜ということです」のような三段構成
   - まず結論を述べ、次に言い換え、最後に具体例で補強するパターン
   - これらは聞き手がリアルタイムに理解を構築するための足場であり、冗長ではない

2. **言い換え・パラフレーズ**
   - 「〜ということは、つまり〜ということですね」
   - 同じ概念を異なる角度から述べることで理解を深めている
   - 文語では重複に見えるが、耳で聞く場合は不可欠

3. **聞き手への問いかけ・注意喚起**
   - 「ここで重要なのは〜ということです」
   - 「ではなぜこうなるのかというと〜」
   - 「〜と思うかもしれませんが、実は〜」
   - 注意を引きつけ、思考を誘導する役割がある

4. **式・概念の丁寧な読み下し**
   - 「この式を丁寧に見ておきましょう。右辺は〜で、左辺は〜です。つまり全体としては〜」
   - 数式を目で見ている聴衆に対して、口頭で意味を解説している
   - これを省略すると理解が断絶する

5. **接続表現・思考の流れを示す表現**
   - 「それなので」「そうすると」「ですから」「つまり」
   - 論理の流れを明示的に示すもの
   - 聞き流してもついていけるようにするための配慮

6. **具体例とその解説**
   - スライドの図表を口頭で説明している部分（「下の図のように〜」「表にあるように〜」）
   - 実世界への応用例の言及

### 変更してよいもの（＝適切な洗練）

1. **明らかなフィラー・言い淀み**
   - 「えーと」「あのー」「ちょっとだけ」等の発話時の癖
   - ただし「ちょっと〜を考えてみましょう」の「ちょっと」は聞き手を誘うニュアンスなので残す

2. **同語反復（意味的に完全に同一の繰り返し）**
   - 完全に同じことを直後に繰り返している場合のみ削除可
   - ただし、少しでも角度が異なれば「パラフレーズ」として残す

3. **文法的な不整合**
   - 主語と述語の不一致、助詞の抜けなどの口語的な文法ミス
   - 意味が変わらない範囲で修正

4. **メタ的な言及の調整**
   - 「次のスライドへ」「このページだけでは」等のスライド操作指示
   - ただし「この図にあるように」は内容に関わるので残す

## 定量的な目安

- **元テキスト比で 85〜100% の行数** を目標とする
  - フォーマット変換（区切り線除去、frontmatter 化）で 10〜15% 減るのは正常
  - 内容の削除による減少は最小限（5% 以内）に留める
- 元テキストの段落構成（＝スライド構成）は完全に維持する
- スライド番号は元スクリプトと一致させる

## TTS 注釈の追加基準

以下に TTS 読み上げ注釈 `[表示](読み方)` を追加する：

1. **英語の専門用語**: `[classification task](クラシフィケーション・タスク)`
2. **略語・頭字語**: `[SVM](エスブイエム)`, `[LLM](エルエルエム)`
3. **数式記号の読み**: `[P(Y|X)](ピー・ワイ・ギブン・エックス)`
4. **モデル名・固有名詞**: `[BERT](バート)`, `[GPT](ジーピーティー)`

注釈の追加は元テキストに**挿入する**形で行い、周囲の文を書き換えない。

## 詳細な読み方のルール

- **アルファベットの読み**:
    - **大文字**: 原則として「おおもじの」または「キャピタル」と読む（例：`[X]` -> `(おおもじのエックス)` または `(キャピタル・エックス)`）．「ラージ」は使用しない．
    - **小文字**: そのまま読む（例：`[x]` -> `(エックス)`）．
    - **ギリシャ文字**: そのまま読む（例：`[θ]` -> `(シータ)`）．
- **数式の読み**:
    - 基本的に、モデル名やパラメーター名などは `[表示](読み方)` 形式で読み仮名を振る．
    - **分数**: `[A/B]` -> `(ビー・ぶんの・エー)`
    - **条件付き確率**: `[P(Y|X)]` -> `(ピー・ワイ・ギブン・エックス)`（縦棒 `|` は「ギブン」と読む）
    - **指数**: `[e^x]` -> `(イーの・エックスじょう)`
    - **総和**: `[Σ]` -> `(シグマ)`、または「そうわ」
    - **平方根**: `[√x]` -> `(ルート・エックス)`
    - **ベクトルや行列**: `[W]` -> `(ダブリュー)`（太字などの区別は文脈に合わせて読み分ける）

## フォーマット変換

- ヘッダー部を YAML frontmatter (`---` ... `---`) に変換
- 区切り線（`===`, `---`, `--- 次のスライドへ ---`）を除去
- スライド見出しを `# [XX-YY: Slide N/M] タイトル` 形式に統一
- `■` 等の装飾記号を除去

## チェックリスト（処理後の確認用）

- [ ] 元スクリプトのすべてのスライドが処理後にも存在するか
- [ ] 元スクリプトの各段落の中身がすべて（言い換え含め）保持されているか
- [ ] 式の読み下し・解説が省略されていないか
- [ ] 具体例が削られていないか
- [ ] 行数比が 85% 以上か（区切り線除去分を勘案）
- [ ] TTS 注釈が必要な箇所に追加されているか

## 失敗パターン（過去の反省）

### パターン1: 要約型圧縮
元テキストの複数段落を1〜2文に「要約」してしまう。
→ 講義の段階的説明が失われ、TTS で聞いたときに唐突な印象を与える。

### パターン2: 口語的冗長性の過剰除去
「ということですね」「そういうわけです」等を削除し文語調にしてしまう。
→ 講義の自然なテンポが失われ、聞きづらくなる。

### パターン3: 接続・思考誘導の省略
「ではなぜこうなるのかというと」を削って直接答えに行ってしまう。
→ 聞き手が考える余地がなくなり、一方的な情報の羅列になる。

### パターン4: スライド枚数の不一致
元スクリプトと異なるスライド枚数でファイルを作成してしまう。
→ 実際のスライドと音声の同期が崩れる。
