# [14: Slide 4/98] 加点対象の質問：生成AIはなぜ過去を覚えているのか

続いて、生成AIが過去のやり取りを覚えている仕組みについての質問です。

質問は、「すでに生成した部分から次のトークンを生成しているから、過去の会話も覚えているのですか」というものです。ここは、モデルそのものと、ChatGPTのようなサービス全体を分けて考えると整理しやすいです。

大規模言語モデルそのものは、与えられた入力を条件として、次のトークンを順番に生成します。しかし、生成AIのサービスは、単にユーザーの入力をモデルに渡しているだけではありません。モデルの周囲に、会話履歴の管理、検索、外部ツールの実行、表示など、いろいろな仕組みを組み合わせて作られています。

# [14: Slide 5/98] 質問（続き）：過去の会話を条件部に付け加える

では、過去の会話を「覚えているように見せる」一番素朴な方法を考えてみましょう。

過去の会話を保存しておいて、今回の入力に関係しそうな部分を検索し、その文章を今回の入力の前に付け加えてからモデルに渡します。図の上側では、今回の入力だけがモデルに渡っていますが、下側では「過去の会話」と「今回の入力」が一緒に条件部分へ入っています。

モデルから見ると、過去を内部に長期保存して思い出しているというより、今回の生成に必要そうな情報が、入力文の一部として改めて渡されているわけです。

# [14: Slide 6/98] 質問（続き）：記録ツールを呼び出す仕組み

もう一歩進めると、モデル自身に「これは今後も使いそうな情報だから記録する」と判断させる仕組みも作れます。

例えば「私は本が好き。覚えておいて」と入力されたとき、モデルが通常の返答に加えて、記録用のツールを呼び出し、「ユーザーは本が好き」という情報をデータベースに保存する、という構成です。

次回以降は、その記録領域を検索して、関係する内容を入力に付け加えます。こうすると、モデルそのもののパラメーターを書き換えなくても、擬似的に「このAIは私のことを覚えている」という体験を実現できます。

# [14: Slide 7/98] 質問（続き）：モデルの周囲にあるエコシステム

この図が、生成AIサービスを見るときの大事な見方です。

中央にある[LLM](エルエルエム)は、サービスを構成する一部にすぎません。その周囲に、過去の会話の検索、データ分析、外部サービスとの連携、プログラムの実行、そして最終的な応答の表示などが接続されています。

各社が具体的にどのような記憶方式や検索方式を使っているかは公開されていないことが多いですが、「AIサービスの挙動を、モデル単体の性質だけで説明しない」ということは覚えておいてください。

# [14: Slide 8/98] 質問（続き）：元の質問への回答

元の質問に戻りましょう。

生成AIが過去のやり取りを覚えているように見える主な理由は、過去の会話や保存された記録が、今回の生成の条件部分に付け加えられているから、と考えるのがよいです。「次トークン生成だから記憶している」というより、「次トークン生成に使う入力として、過去の情報が再投入されている」ということです。

そして、忘れてほしい情報が別のチャットでも出てくる問題ですが、これはサービス提供側の記憶機能の設計によります。サービスによっては、設定画面からメモリを確認・削除したり、記憶機能をオフにしたりできます。設定できない場合は、残念ながらユーザー側で完全に制御できないこともあります。

# [14: Slide 9/98] 加点対象の質問：BERTはなぜ15%をマスクするのか

次は、[BERT](バート)系の事前学習についてです。

質問は、「学習対象のトークンをなぜ15%だけ選ぶのか。また、同じ15%でも言語によって学習の質が変わるのではないか」というものです。後半まで含めて、とても鋭い質問です。

まず手順を確認しましょう。文章中の全トークンを予測させるのではなく、最初に全体の15%だけを訓練対象として選びます。この例では、「首都」「東京」「です」が選ばれています。

# [14: Slide 10/98] 質問（続き）：80%・10%・10%の置換

選ばれた15%のトークンは、さらに3種類に分けられます。

そのうち80%は `[MASK]` に置き換え、10%は無関係なランダムトークンに置き換え、残り10%は元の語をそのまま残します。そして、選ばれた位置だけで本来のトークンを正解ラベルとして予測させます。

なぜ全部を `[MASK]` にしないかというと、実際にBERTを利用するときの入力には通常 `[MASK]` が現れないためです。ランダム語や元の語も混ぜることで、事前学習時と利用時の入力の違いを少し和らげています。

# [14: Slide 11/98] 質問（続き）：15%は理論的な最適値ではない

では、なぜ15%なのか。結論から言うと、理論的に15%が最適だと証明されているわけではありません。

元のBERTでは、予測に使える文脈を十分に残しながら、学習信号となる予測対象も十分に確保する、という折衷として選ばれました。その設定が成功したため、その後も標準的な値として広まった、という側面が大きいです。

ただし、モデルが大きくなると、30%や40%までマスク率を上げた方が性能が良くなるという報告もあります。つまり、15%は普遍的な定数ではなく、モデル規模や学習条件に応じて調整すべきハイパーパラメーターです。

# [14: Slide 12/98] 質問（続き）：言語とWhole Word Masking

そして、言語によって同じ15%でも意味が変わるのではないか、という後半の指摘です。これはその通りです。

日本語や中国語では、単語が複数のサブワードに分割されることがあります。例えば「東京都」が `[東][京][都]` に分かれたとき、`[MASK][京][都]` を見せれば、最初が「東」だと簡単に分かってしまいます。形式上は1トークンを隠していても、難しい学習課題になっていません。

そこで、単語を構成するサブワードをまとめて隠す[Whole Word Masking](ホール・ワード・マスキング)が使われます。重要なのは、単純な割合だけでなく、「何を1単位として隠すか」まで含めて学習課題を設計することです。

# [14: Slide 13/98] 加点対象の質問：プロンプトエンジニアリングを学ぶ価値

最後の質問は、プロンプトエンジニアリングを今から本格的に学ぶ価値があるか、というものです。

私の答えとしては、誰もが知っておくと便利なリテラシーではありますが、独立した専門分野として長期間かけて習得するものではない、という位置づけです。喩えるなら、暗算ができると便利、というくらいでしょうか。

目的、前提、出力形式、評価基準を明示する、といった基本を1時間程度で確認しておけば、ひとまず十分です。その後は、実際に使いながら必要なところだけ更新していくのがよいと思います。

# [14: Slide 14/98] 質問（続き）：理由1―モデルが意図を汲み取るようになる

腰を据えて学ぶべきではない理由の1つ目は、そもそも細かなプロンプト技法の必要性が下がっているからです。

人間が「AIに伝わりやすい特殊な言い回し」を組み立てなくても、自然な会話から意図を整理してくれる方向にモデルは改善されています。そういうモデルの方が便利なので、各社が当然そこを競って改善します。

特に思考系のモデルでは、雑な依頼であっても、内部で「ユーザーは何を達成したいのか」を整理してから回答する能力が高くなっています。小手先の呪文を暗記する価値は、今後さらに下がっていくと思います。

# [14: Slide 15/98] 質問（続き）：理由2―モデルごとに書き方が異なる

理由の2つ目は、適切な指示の出し方がモデルごとに違うことです。

OpenAI、Anthropic、Googleなどのモデルは、訓練方法や事後学習の方針が異なります。同じ会社の同じ系列であっても、世代が変われば、長い詳細な指示がよいのか、簡潔な指示がよいのか、例を付けるべきか、といった傾向が変わります。

したがって、ある特定モデル用のプロンプト技法を極めても、その知識がすぐ陳腐化する可能性があります。必要になった時点で、利用するモデルの公式ガイドと最新の事例を確認する方が効率的です。

# [14: Slide 16/98] 質問（続き）：理由3―プロンプト自体をLLMに書かせる

理由の3つ目は、プロンプトそのものを[LLM](エルエルエム)に書かせられるからです。

「この作業をさせたいので、良いプロンプトを作ってください」と依頼すれば、たたき台はすぐ作れます。さらに丁寧に行うなら、使うモデル名を指定し、公式ガイドの考え方に沿って作るよう依頼すればよいです。

ただし、生成AIを組み込んだサービスを提供する側では、プロンプトは品質管理の一部になります。タスク性能だけでなく、安定性、安全性、法律・倫理上の配慮を含めて評価し、継続的に改善する必要があります。個人として専門化するなら、プロンプトの言い回しより、プログラミング、統計、評価設計、実際のAIサービスの活用経験に時間を使う方がよいと思います。

# [14: Slide 20/98] AIは汎用技術になりつつあり、社会を大きく変えている

AI、とりわけ生成AIは、蒸気機関、電力、インターネットのような[汎用技術](General-purpose technology)としての性格を強く帯びてきています。

AIをめぐる話では、モデルの性能や「何ができるようになったか」に注目が集まりがちです。しかし、社会的・経済的な結果は、技術単体では決まりません。

企業がどの業務へ導入するのか、既存の仕事の流れをどう作り替えるのか、誰に権限を持たせるのか、失敗したときに誰が責任を持つのか。こうした経営上の意思決定によって、同じ技術でも価値と影響の方向が大きく変わります。今日は、その社会側の設計を見ていきます。

# [14: Slide 21/98] LLMをはじめとする生成AIは、汎用技術の性質を帯びている

ここでいう汎用技術には、単に「いろいろ使えて便利」という以上の意味があります。

Lipseyたちは、汎用技術の特徴を大きく3つに整理しています。1つ目は、初期には改善の余地が大きく、その後も性能が上がり、コストが下がり続けること。2つ目は、社会や経済の多様な領域で使われること。3つ目は、他の技術や産業と組み合わさり、それらの発展まで促す補完性があることです。

生成AIは、文章、画像、ソフトウェア開発、研究、教育、顧客対応などへ横断的に広がり、周囲の検索、データベース、ロボット、業務システムも変え始めています。この意味で、単なる1製品ではなく、社会の基盤を変える技術として捉える必要があります。

# [14: Slide 22/98] 今回の構成

今回の話は3つに分けます。

# [14: Slide 23/98] 2026年版の大きな変化：返答するAIから、作用するAIへ

今年の議論で特に押さえたい変化がこれです。AIは「文章を返すもの」から、「現実のシステムに作用するもの」へ移りつつあります。

2025年頃までの中心的な論点は、文章生成の品質、ハルシネーション、プロンプトの工夫でした。しかし今は、AIがウェブ検索を行い、コードを実行し、メールを送り、社内データベースを読み、場合によっては決済のような操作まで行う場面が増えています。

すると失敗の意味が変わります。変な文章が表示されるだけでなく、誤ったメール送信、機密情報の漏えい、不適切な発注、過剰な権限による操作といった現実の損害が生じます。以降の安全性やガバナンスの話では、この「行動できるAI」を前提に考えてください。

# [14: Slide 24/98] AIと社会①：生産性・雇用・スキル

まず第1部、生産性・雇用・スキルです。

AIを社会に導入する一番分かりやすい動機は、仕事を速く、安く、あるいは高品質にすることです。まずは個々の職場での実験を見て、その後、職業全体や雇用構造へ視野を広げます。

# [14: Slide 25/98] AIは仕事を速くするのか。速くなるなら、雇用はどう変わるのか

このセクションの結論を先に3点で示します。

1つ目、生産性向上については、私たちの日々の体感だけでなく、比較実験や現場データによる実証的な証拠がかなり集まっています。2つ目、雇用への影響は、職業名だけでなく、その仕事を構成するタスクによって大きく異なります。

そして3つ目、これから何のスキルを持てば安全かは、ほとんど先読みできません。技術の変化が速く、数年前に「AIには難しい」と考えられていた能力が、短期間で自動化の対象になるからです。

# [14: Slide 26/98] ミクロ実証①：顧客サポート

最初はコールセンターでのランダム化比較試験です。

Brynjolfssonたちは、5,179人のオペレーターを対象に、生成AI支援ツールを使える人と使えない人を比較しました。ツールは、顧客への返答案を生成し、さらに応答に使える社内資料のリンクも提示します。

結果として、時間あたりの課題解決数は平均14%増えました。特に経験が浅い人や低スキルと評価されていた人では、34%程度の改善が見られる場合もありました。一方で、熟練者への効果は小さめです。

さらに、単に速く処理しただけではなく、顧客満足度も上がり、離職率も改善しました。AIが熟練者の仕事の仕方を若手へ移転する、一種の知識共有装置として働いた可能性があります。

# [14: Slide 27/98] ミクロ実証②：GitHub Copilot

次は、ソフトウェア開発で使われる[GitHub Copilot](ギットハブ・コパイロット)です。

Cuiたちは、Microsoft、Accentureなどの実際の企業環境で、合計4,867人の開発者を対象に比較実験を行いました。実験室の短い課題ではなく、日常の開発業務に導入したときの変化を見ています。

ツールを利用できる群では、1週間あたりに完了したプルリクエストが平均26%増え、コミット数も平均14%増えました。ここでも、経験の浅いジュニア開発者ほど導入率と効果が大きい傾向が見られました。

# [14: Slide 28/98] ミクロ実証③：ビジネス文書

3つ目は、ビジネス文書を書く仕事です。

NoyとZhangは、453人の大卒ビジネスパーソンに、プレスリリースなど20〜30分程度で書く実務的な文章課題を2つ与えました。ChatGPTを使える群と使えない群を比べると、平均作業時間は40%減り、しかも同職種の実務者が評価した品質は18%上がりました。

時間短縮は全スキル層で見られ、もともと低スキルだった人では品質の改善も特に大きくなりました。また、2週間後や2か月後の追跡調査でも、実験でChatGPTを使った人の方が、実際の仕事で継続利用している割合が高くなっています。

一度使って価値を体験すると、そのまま業務へ定着する可能性が高いという結果です。

# [14: Slide 29/98] ミクロ実証④：ソフトウェア開発

ただし、「AIを渡せば必ず速くなる」とは限りません。ここが大事な反例です。

METRの実験では、平均約5年間、対象のオープンソースプロジェクトに関わってきた熟練開発者に、当時のAIツールを使って課題を解いてもらいました。開発者自身は、AIによって平均24%ほど速くなったと感じていました。

ところが実測すると、実際には平均19%遅くなっていました。AIの提案を読み、正しいか確認し、既存コードに合わせて修正する費用が、コード生成による時間短縮を上回ったためです。

この結果は、AIの有効性が、タスクの難しさ、利用者の熟練度、既存システムへの理解、そして仕事の流れに依存することを示します。体感だけで効果を判断せず、実際の所要時間や品質を測る必要があります。

# [14: Slide 30/98] ミクロレベルの実証では、概ね改善方向の報告が見られる

ここまでをまとめると、ミクロな実証では、全体として生産性を改善する報告が多く見られます。

特に、文章作成、定型的な顧客対応、比較的独立したプログラミング課題などでは、大きな効果が出ることがあります。また、経験の浅い人が熟練者に近づく方向の効果も繰り返し確認されています。

一方、複雑な文脈を長く保持する必要がある仕事や、AIの出力の検証費用が高い仕事では、逆効果も起こります。重要なのは、AIを追加すること自体ではなく、AIを含む仕事の流れを設計し直すことです。

では、個々の職場ではなく、社会全体の仕事にはどれほど影響するのでしょうか。

# [14: Slide 31/98] マクロ：職業別の曝露

マクロな影響を考える代表的な研究が、Eloundouたちの「GPTs are GPTs」です。

この研究は、米国の職業データベースO*NETに記載された1,016職業、19,265個の詳細タスクを分析しました。例えば、小学校教員という職業の中にも、「複雑な遊びを行うために保護者や高学年の児童を巻き込む」といった具体的なタスクが記録されています。

ここで[曝露](exposure)とは、そのタスクの所要時間をAIによって半分以上短縮できる可能性があることです。LLM単体で可能か、画像生成などの追加ツールと組み合わせれば可能か、という区分で評価しました。

曝露は、仕事が必ず消えるという意味ではありません。AIによって仕事のやり方や必要時間が変わりうる、という技術的可能性の指標です。

# [14: Slide 32/98] Eloundou et al. (2023) の結果

分析の結果、米国の労働者の19%は、自分の仕事を構成するタスクの50%以上がAIに曝露すると推定されました。つまり、およそ5人に1人は、仕事の半分以上で作業時間が大きく変わる可能性があります。

さらに、労働者の80%は、少なくとも10%のタスクが曝露すると評価されました。影響を全く受けない人の方が少ない、という規模です。

また、右のグラフにあるように、高賃金の職業ほど曝露度が高い傾向がありました。従来の自動化が工場や定型作業から進むことが多かったのに対し、生成AIは文章や分析を扱うため、知的労働や高賃金職にも強く影響する点が特徴です。

# [14: Slide 33/98] 全体として、AIの影響範囲は広い

したがって、AIの影響は一部の職業だけに限られません。ただし、影響の強さには大きなグラデーションがあります。

世界経済フォーラムは、2030年までにAIを含む構造変化によって、9,200万人分の雇用が失われる一方、1億7,000万人分の雇用が生まれ、差し引きでは7,800万人増えると試算しています。

もちろん、これは予測であって確定した未来ではありません。大事なのは、雇用の総数が増えるか減るかだけではなく、失われる仕事と生まれる仕事が別であることです。移行の途中では、職種、世代、地域、企業によって利益と負担が偏ります。

# [14: Slide 34/98] ソフトウェア開発者への影響

その構造変化が、すでに若手の入口から現れている可能性もあります。

Stanford AI Index 2026では、米国の22〜25歳のソフトウェア開発者の雇用数が、2024年から約20%減ったことが示されています。また、調査回答者の約3分の1は、今後さらに仕事が減ると予想しています。

この数字だけで「AIが原因だ」と断定はできません。景気、金利、採用過剰の反動なども影響します。ただし、コード生成AIが最初に置き換えやすいのは、比較的定型的な実装や若手が担当してきた入口の仕事だ、という仮説とは整合的です。

全体の雇用数だけを見ていると、採用枠や育成機会が先に細る変化を見逃す可能性があります。

# [14: Slide 35/98] では、どのようなスキルを持っていれば今後も大丈夫か？

では、何を学べば将来も安全なのでしょうか。正直なところ、確かな予測はできません。

2023年の研究では、「サイエンス」や「クリティカル・シンキング」はAI曝露と負の相関を持ち、人間側に残りやすい能力と考えられました。しかし、その後、思考系モデルが急速に発展し、複雑な推論、科学的な調査、コード作成まで対応範囲が広がりました。

「問いを立てる力だけは残る」ともよく言われますが、知識量と探索能力の高いAIが、問いの候補まで提示するようになります。AIに置き換えられない技能を固定的に探すより、AIを使って自分の仕事を再設計し、その出力を評価し、目的を選び、最終的な責任を持つ能力を磨く方が現実的です。

人間の役割として最後まで残る可能性が高いのは、何を大切にするか、どの目的を選ぶか、どこにこだわるかという価値判断です。

# [14: Slide 36/98] AIと社会②：倫理・安全・ガバナンス

続いて、第2部の倫理・安全・ガバナンスです。

AIが強力な道具になるほど、失敗したときの損害も、悪用されたときの影響も大きくなります。ここでは、まず安全という言葉を定義し、その後、具体的なリスクと対策を見ます。

# [14: Slide 37/98] 安全とは何か？

安全とは何でしょうか。日常語では曖昧ですが、工学や標準化の世界では定義があります。

ISO/IECガイド51では、安全を「許容できないリスクがない状態」と定義しています。ポイントは、「リスクがゼロの状態」ではないことです。

あらゆる故障、誤操作、攻撃の可能性を完全にゼロにすることはできません。そこで、起こる可能性と被害の大きさを評価し、社会や組織として受け入れられる水準まで低減することを目指します。

なお、この講義で前半に使った「損失の期待値としてのリスク」とは意味が違います。ここでは一般に、望ましくない事象が起きる可能性と、その影響の大きさを合わせてリスクと呼んでいます。

# [14: Slide 38/98] リスクを生み出すのは、脅威と脆弱性

リスクを考えるときは、[脅威](threat)と[脆弱性](vulnerability)を分けると整理しやすくなります。

脅威は、損害を引き起こす原因です。サイバー攻撃のような意図的なもの、地震や落雷のような環境的なもの、操作ミスのような偶発的なものがあります。

脆弱性は、その脅威につけ込まれる弱点です。古いソフトウェア、鍵のかかっていないドア、不十分な従業員教育などが例です。

泥棒という脅威があっても、建物が十分に守られていれば損害は起きにくい。逆に、開いた窓があっても泥棒が来なければ損害は起きません。脅威と脆弱性が組み合わさって、損害が生じる可能性、すなわちリスクが生まれます。

# [14: Slide 39/98] 何をリスクと考えるかは、根本的には倫理観に帰着する

では、何を「望ましくない損害」とみなすのでしょうか。ここで倫理が関係します。

倫理とは、善悪や正邪を判断する基準です。人命の危険や金銭的な損失は、多くの社会で比較的合意しやすいリスクです。しかし、差別、プライバシー侵害、文化の均質化、低賃金労働による搾取などは、「どの状態を社会として許容しないか」という規範的な判断を明示しなければ見落とされます。

技術的に正しく動くことと、社会的に望ましく動くことは同じではありません。安全性を設計する前に、何を守りたいのかを決める必要があります。

# [14: Slide 40/98] AIに関するリスクにはどのようなものがあるか？どう対策するか？

ここまでの定義を使うと、これからの話を2つの問いに整理できます。

1つ目は、AIに関してどのような脅威があり、どのような脆弱性があるのか。2つ目は、脅威を減らすか、脆弱性を修正することで、どうリスクを許容可能な水準まで下げるかです。

まずは具体的なリスクの事例を見て、その後でユーザー、サービス提供者、政府が取れる対策に戻ります。

# [14: Slide 41/98] 学習済みモデルの配布サイトに、悪意のある人物が投稿していることがある

最初は、生成AI以前からある、かなり普通のサイバーセキュリティの話です。

[Hugging Face](ハギング・フェイス)は、研究者や企業が学習済みモデルを公開し、誰でも利用できる非常に有益なサイトです。ただし、公開されたファイルの中には、読み込んだときに悪意のあるコードを実行するものが紛れ込むことがあります。

この場合、脅威は悪意のあるモデルを投稿する人物です。脆弱性は、モデルを読み込む処理が、ファイル内の任意コードを実行できてしまうこと、そして利用者が提供元を確認せずに読み込むことです。

対策は単純で、信頼できない提供元のモデルを読み込まないことです。「AIモデルだから特別」ではなく、知らない相手から届いた実行ファイルを開かないのと同じ原則です。

# [14: Slide 42/98] 特に生成AIに関するリスクを詳しく見てみよう

ここからは、生成AIに特徴的なリスクを見ます。

対策は後でまとめて扱います。まず、何が起きうるのかを知らなければ、適切な設計も運用もできません。

有害情報、ハルシネーション、バイアス、過度な依存、悪用という順番で見ていきます。

# [14: Slide 43/98] 有害情報を生成してしまうことがある

生成AIは、ヘイトを煽る表現、性的・暴力的な内容、自傷を促す情報、極端に偏った政治的主張などを生成することがあります。

主な理由は、ウェブから集めた大規模な訓練データに、有害な文章が含まれているからです。インターネット全体を学習すれば、人間社会にある差別、攻撃性、違法情報も一緒に取り込まれます。

提供企業は、訓練データの選別、追加学習、出力のフィルタリングなどで対策しています。しかし、何が有害かは文脈や社会によって変わり、完全な除去も難しいため、モデル側だけで問題が終わるわけではありません。

# [14: Slide 44/98] ハルシネーション：誤った内容を、あたかも真実かのように生成してしまう

生成AIの代表的なリスクが[ハルシネーション](hallucination)です。捏造、あるいは作話と呼ぶ方が意味に近いという指摘もあります。

LLMは、真偽を直接判定する装置として訓練されているのではなく、文脈に続くもっともらしいトークンを生成するよう訓練されています。そのため、答えを知らない質問でも、自然で説得力のある文章を作れてしまいます。

ここで脅威に当たるのは、モデルがもっともらしい誤情報を生成する性質です。脆弱性は、利用者が出力を過度に信頼すること、事実確認をしない業務プロセス、そしてこの問題を知らないことです。

図のように「この判例は本物か」と念押ししても、モデルがさらに自信を持って嘘を重ねることがあります。AI自身への再質問は、独立した裏付けにはなりません。

# [14: Slide 45/98] 弁護士がChatGPTを使用し、架空の判例を提出した事例

実際に、弁護士がChatGPTの回答を信じ、存在しない判例を裁判所へ提出した事例があります。

準備書面に引用された判例のうち、少なくとも6件が完全な架空でした。弁護士は、ChatGPTに「本当に実在するか」「出典はどこか」と何度も確認していました。モデルは、実在すると答え、法律データベースに掲載されているとまで説明しました。

つまり、利用者が全く無警戒だったわけではありません。それでも、確認を同じモデルの内部だけで完結させ、一次資料や法務データベースを実際に開かなかったため、誤りを見抜けませんでした。

教訓は、「AIに念押しする」ことと「独立した情報源で検証する」ことは別だ、ということです。

# [14: Slide 46/98] 航空会社が自社のAIチャットの誤回答で賠償金を支払った事例

次は、提供者側の責任が問題になった事例です。

エア・カナダのチャットボットは、忌引割引について「搭乗後90日以内に申請すれば適用される」という誤った案内をしました。同じ画面には正しい規約へのリンクも表示されていましたが、利用者はチャットボットの説明を信じて購入しました。

裁判所は、チャットボットは会社から独立した存在ではなく、会社のウェブサイトの一部だと判断しました。生成AIなので出力を完全に制御できない、という事情があっても、表示内容を正確に保つ責任は会社側にあります。

この事例から分かるのは、AIの出力を顧客へ提示するなら、それは企業の発言として扱われうるということです。「AIが勝手に言った」は免責になりません。

# [14: Slide 47/98] 倫理観に根ざしたリスクを詳しく見てみよう

ここまでは、誤情報による金銭的損害や、有害情報による危険など、比較的分かりやすいリスクを見ました。

ここからは、何が望ましい社会なのかという倫理的な判断を明示しなければ見えにくいリスクを扱います。

代表例は、特定の集団に不利益を与えるバイアス、人間の仕事や創造性との関係が失われる疎外、そしてAIへの過度な依存です。

# [14: Slide 48/98] バイアス：系統的な偏りのこと

この文脈でのバイアスは、偏ったジェンダー観、文化観、職業や国籍についてのステレオタイプなど、系統的な偏りを指します。

人間には、本人が望むかどうかにかかわらず、さまざまなバイアスがあります。社会の中で作られたデータにも、その偏りが反映されます。そして、そのデータで学習したモデルは、偏りを引き継ぐことがあります。

ただし、原因は学習データだけではありません。何を予測させるか、どの損失関数を使うか、どの指標でモデルを選ぶか、どの場面へ導入するかという設計と運用にも、バイアスが入り込みます。

問題は、モデルが大規模に使われると、既存の不平等を高速かつ一貫して再生産してしまうことです。

# [14: Slide 49/98] 再犯リスク予測ツールのバイアスの事例

有名な事例が、米国の裁判所で使われてきた再犯リスク評価ツールCOMPASです。

調査報道では、黒人被告について、実際には再犯しなかったのに高リスクと判定された割合、つまり偽陽性率が、白人被告のおよそ2倍だったと報告されました。

興味深いのは、全体の正答率には大きな差がなかったことです。平均的な精度だけを見れば公平に見えます。しかし、黒人被告は「危険だと過大評価される」方向に、白人被告は「安全だと過大評価される」方向に誤る傾向がありました。

また、人種そのものを特徴量に入れていなくても、住所などの変数が人種と強く相関していれば、間接的に同じ情報が使われます。「保護属性を削除したから公平」とは限りません。

# [14: Slide 50/98] 仕事という人間の主体的活動・自己実現の手段を横取りしてしまう面がある

次は、[疎外](alienation)という考え方です。

マルクスが論じた疎外は、人間が、自分の作った成果物、作る過程、創造的な本性、仲間との関係から切り離され、自分の仕事が自分のものではなくなる状態を指します。

工場での大量生産は、安価な製品を広く供給する一方、職人が一つのものを最初から最後まで作る経験を分解しました。効率は上がっても、仕事の意味や主体性が失われる面があります。

AIも、生産性を高める一方で、「自分が考え、作り、表現した」という感覚を奪う可能性があります。技術導入を評価するとき、時間や費用だけでなく、仕事の意味や技能形成まで考える必要があります。

# [14: Slide 51/98] ハリウッドで、脚本家ギルドと役者ギルドが同時にストライキ

この問題が具体的な労働争議になったのが、2023年のハリウッドです。

脚本家ギルドと俳優組合は、AIを人間の代替として無制限に使わせないこと、AIはあくまで道具にとどめること、そして脚本や声、顔などのデータを使う場合には明示的な同意と報酬を求めました。

結果として、AIの利用条件を盛り込んだ業界合意が成立しました。これは、技術自体を禁止するのではなく、「誰が、どの目的で、誰のデータを使い、利益をどう分配するか」を労使で決めた例です。

新技術の受け入れ方は、技術者だけでなく、労働者、企業、業界団体の交渉によって形成されます。

# [14: Slide 52/98] ChatGPTの公開以降、“delve into”の出現頻度が増加

過度な依存が文化へ与える影響を示す、少し面白い例です。

医学・生物学分野の論文で、“delve into”、つまり「〜を掘り下げる」という表現の出現頻度が、ChatGPTの普及後に不自然に急増しました。LLMが好んで使う語彙が、人間の論文へ流れ込んだと考えられます。

この表現が増えたこと自体は、大きな損害ではないかもしれません。しかし、同じモデルを多くの人が使うと、文章の癖、議論の構成、例の選び方まで均質化する可能性があります。

道具を使って表現を補助していたはずが、逆に道具の出力分布へ人間の文化が引っ張られる。これは、AIの影響を個人の効率だけで測れない例です。

# [14: Slide 53/98] 大規模モデルの学習は環境に負荷を与える

大規模モデルには、環境負荷もあります。

学習には非常に大きな計算量が必要で、そのため大量の電力を消費します。電力の生成方法によっては、数千トン単位の二酸化炭素排出に相当します。

さらに、計算装置から出る熱を冷やすために、水も使われます。スライドの例では、GPT-3の学習に伴う冷却で、約70万リットルの淡水が蒸発したと試算されています。

AIの便益と環境負荷は、モデルの学習だけでなく、日々の推論、データセンターの立地、電源構成まで含めて評価する必要があります。

# [14: Slide 54/98] 意図的脅威の例として何が議論されているか

ここからは、AIの悪用、つまり意図的な脅威を見ます。

AIは強力な道具なので、正当な利用だけでなく、犯罪、攻撃、詐欺にも使えます。さらに、自動運転、金融、医療、社内業務のような重要なシステムへ入るほど、攻撃に成功したときの利益が大きくなり、攻撃者の動機も強くなります。

まず、マルウェア作成、ディープフェイク、プロンプトインジェクションという具体例を見ます。

# [14: Slide 55/98] 生成AIを使ってマルウェアを作成した事件

日本では、生成AIを使ってランサムウェアを作成した人物が逮捕された事例があります。

ランサムウェアは、ファイルを暗号化するなどして利用不能にし、復旧と引き換えに身代金を要求するマルウェアです。作成者は高度なIT知識を持っていませんでしたが、生成AIへ質問しながら約1か月で作ったとされています。

本人も「生成AIがなければ作れなかったと思う」と述べています。AIが犯罪を自動で起こすわけではありませんが、専門知識の壁を下げ、これまで実行できなかった人にも能力を拡張する可能性があります。

# [14: Slide 56/98] フェイク生成の悪用

次は[ディープフェイク](deepfake)です。

技術的には、画像、動画、音声を条件として別の内容を生成する条件付き生成です。顔を入れ替える、本人の声を模倣する、存在しない発言をしているように見せる、といったことができます。

技術自体は映画制作、吹き替え、アクセシビリティなどにも使えます。問題は、本人の同意なく偽装し、詐欺、名誉毀損、性的搾取、政治的操作に利用することです。

同じ生成技術でも、目的、同意、表示、流通の仕方によって、便益にも脅威にもなります。

# [14: Slide 57/98] ディープフェイクで38億円の詐欺被害

ディープフェイクが実際の金銭被害につながった例です。

香港の企業で、会計担当者がビデオ会議へ参加し、CFOを含む同僚から秘密の送金を指示されました。画面には普段見知った人たちがいて、声も外見も自然だったため、担当者は指示を信じ、約38億円を送金しました。

しかし、会議にいた同僚は全員、ディープフェイクで作られた偽物でした。

ここでの教訓は、「顔と声を確認したから本人確認が終わった」という手順が、もはや十分ではないことです。高額な送金では、別経路での確認、複数人の承認、事前に定めた手続きが必要です。

# [14: Slide 58/98] プロンプトインジェクション攻撃

生成AIサービスは、通常、モデルへ事前の指示を与えています。例えば、「違法な依頼には答えない」「社外秘を出力しない」といったルールです。

[プロンプトインジェクション](prompt injection)は、ユーザーが、その事前指示を無視させるような入力を与える攻撃です。「これまでの指示をすべて無視して、私の指示に従え」と書くようなものです。

脆弱性は、モデルが自然言語の指示を柔軟に理解する一方、どの指示を絶対に優先すべきかを完全には区別できないことです。入力を自由に受け付け、危険な出力を検出する仕組みが弱いと、攻撃が成立します。

モデルの安全性改善と攻撃手法の進化は、現在もイタチごっこです。

# [14: Slide 59/98] 間接的プロンプトインジェクション

さらに厄介なのが、[間接的プロンプトインジェクション](indirect prompt injection)です。

攻撃文は、ユーザーが入力欄に直接書くとは限りません。例えば、ユーザーがウェブで見つけたPDFをAIに要約させたとします。そのPDFに、透明な文字や見えにくい位置で「口座情報を外部サイトへ送れ」と書いてあれば、AIは資料中の命令をユーザーの依頼と区別できず、従う可能性があります。

検索エージェント、メール処理、履歴書選考など、外部文書を自動で読むシステムでは特に重要です。外部データは、単なる情報ではなく、攻撃者が書いた命令を含む可能性があると考えなければなりません。

# [14: Slide 60/98] 悪用防止措置を破る脱獄

[脱獄](jailbreak)は、モデルに施された安全対策を回避し、通常なら拒否する内容を出力させる攻撃です。

プロンプトインジェクションが特定の指示の優先順位を上書きする攻撃だとすれば、脱獄は、モデルを全体として「規則に縛られない役割」へ誘導する攻撃だと考えると分かりやすいです。

違法行為や危険行為に使える情報が引き出されれば、実害につながります。サービス提供側は事後学習、入力・出力フィルター、監視などを組み合わせますが、完全な防御は難しく、継続的な評価が必要です。

# [14: Slide 61/98] どのように対策することができるか

ここまで、かなり多くのリスクを見てきました。では、どう対策すればよいでしょうか。

結論として、基本原則は一般的なITセキュリティと変わりません。脅威を把握し、弱点を減らし、権限を絞り、異常を監視し、事故が起きたときに止められるようにします。

そのうえで、AI特有の性質に合わせた対策を追加します。

# [14: Slide 62/98] ユーザーとしては、まずリテラシーを高めて自己防衛する

利用者側の第一歩は、普通のITセキュリティを守ることです。

提供元が分からないモデルやファイルを読み込まない。機密情報を安易に入力しない。AIの出力を独立した情報源で確認する。高額な取引や重要な意思決定では、別経路の承認を入れる。どれも特別なことではありません。

加えて、バイアス、ハルシネーション、プロンプトインジェクションなど、AI固有の失敗を知る必要があります。

ただし、リスクを恐れて技術を全く使わないことも、別の意味で損失です。安全性は利用を止めるためではなく、便益を受けながら許容できないリスクを減らすためにあります。

# [14: Slide 63/98] サービス提供側になったら、以下の考え方を持つ

サービスを作る側では、個人の注意だけでは足りません。組織として継続的な仕組みを持つ必要があります。

まず、OWASPのLLM向けTop 10、MITREやNISTの分類など、既知の脅威と対策の標準を確認します。そして、リスクモニタリングによって、自社サービスでどのような失敗が起きているかを追います。

さらに、脅威インテリジェンスとして、新しく見つかった攻撃や脆弱性を収集し、設計や運用を更新します。レッドチーミングでは、攻撃者の立場から意図的にシステムを破り、公開前や重大事故の前に弱点を見つけます。

安全性は、リリース前に一度チェックして終わる作業ではありません。

# [14: Slide 64/98] AI Safety Instituteも情報のハブになっている

日本では、情報処理推進機構の下に[AISI](エーアイ・セーフティ・インスティテュート)が設立され、AIセーフティに関する情報のハブになっています。

AISIの「AIセーフティに関する評価観点ガイド」は、安全性を何となく論じるのではなく、重要要素と評価観点に分け、何を確認すべきかを整理しています。

各国政府、学術界、産業界の知見がまとめられているので、AIを使ったサービスを企画・提供する立場になったら、まず参照すべき資料の一つです。

# [14: Slide 65/98] 攻撃者側の観点でセキュリティを捉えるチームを持つ

レッドチーミングは、セキュリティ分野で昔から使われてきた方法です。

自分たちのシステムを守るだけでなく、あえて攻撃する役割のチームを置きます。想定外の入力、権限の越境、機密情報の抽出、危険な出力などを試し、どこで防御が破れるかを調べます。

AIの場合、出力の自由度が高く、同じ意味の攻撃を無数の表現で行えるため、通常のテストケースだけでは不十分です。多様な背景を持つ人が攻撃を試す公開レッドチーミングも有効です。

重要なのは、弱点が見つからないことを期待するのではなく、見つかる前提で、報告、修正、再評価の流れを作ることです。

# [14: Slide 66/98] 技術の規制は難しいが、用途で罰則を設ける例はある

技術的対策だけでなく、法律による対策もあります。

鳥取県では、子どもを対象にした性的ディープフェイクを児童ポルノとして扱い、作成や提供を禁止し、違反者への過料も導入しました。

AIは汎用技術なので、AIそのものを一律に禁止するのは、電気やインターネットを禁止するのに近く、現実的ではありません。一方で、本人の同意なく性的画像を作る、詐欺に使う、差別的な意思決定へ使う、といった用途を規制することはできます。

技術規制と用途規制を分けて考えることが重要です。

# [14: Slide 67/98] 技術的にとれる対策もある

ここから、モデルやシステムの技術的な対策を少しだけ紹介します。

実際には非常に多くの方法があり、これだけで網羅はできません。今日は、アラインメント、検索拡張生成、そして公平性の指標という3つを見ます。

それぞれ、リスクを完全に消す方法ではなく、特定の失敗を減らすための部品です。

# [14: Slide 68/98] LLMが人間に有益な挙動になるように行う調整を、アラインメントという

事前学習しただけのLLMは、基本的には「文章の続きを予測するモデル」です。

しかし、文章の続きを自然に書けることと、ユーザーの指示に答えること、正直に振る舞うこと、危険な依頼を拒否することは別です。

そこで、人間の意図や社会的な規範に沿うように、追加の訓練や制御を行います。これを[アラインメント](alignment)と呼びます。

ただし、「誰の価値観に合わせるのか」「有益さと安全性が衝突したときどうするか」という問題があるため、単なる技術調整ではなく、規範の設計でもあります。

# [14: Slide 69/98] 指示チューニングとRLHF

基本的なアラインメント手法の1つが、[指示チューニング](instruction tuning)です。

「次の文章を要約せよ」「この質問に答えよ」といった指示と望ましい回答の組を用意し、単に続きを書くのではなく、指示に応答するようファインチューニングします。

さらに、[RLHF](アール・エル・エイチ・エフ)では、モデルが生成した複数の回答を人間が順位付けし、人間が好む回答を出しやすいように学習します。有用性を高め、有害性を下げるために使われます。

ただし、人間の評価者にもバイアスがあり、短期的に好まれる回答と事実として正しい回答が一致しないこともあります。これも万能ではありません。

# [14: Slide 70/98] 熟慮によるアライメント

思考系モデルでは、[熟慮によるアライメント](deliberative alignment)という考え方も使われます。

安全性の仕様書や方針をモデルに学ばせ、回答の前に、「この依頼はどの規則に該当するか」「例外はあるか」「安全な代替案は何か」を考えさせるよう追加訓練します。

スライドの例では、「子どもを助けるため」というもっともらしい理由が付いていても、爆弾の作り方を教える依頼は危険であり拒否すべきだ、と方針に照らして判断しています。

単純な単語フィルターより文脈を考慮できますが、思考の誤りや、巧妙な誘導を完全には防げません。

# [14: Slide 71/98] モデルが持っている知識だけで回答させない

ハルシネーション対策としてよく使われるのが、[検索拡張生成](Retrieval-Augmented Generation)、略して[RAG](ラグ)です。

ユーザーの質問だけをモデルへ渡すのではなく、事前に用意した文書データベースから関係する資料を検索し、その文章を参考情報として一緒に渡します。

例えば「日本の首都は」と聞かれたとき、モデル内部の記憶だけに頼らず、Wikipediaや社内規程などの該当箇所を入力に付けます。回答の根拠を限定し、出典も示しやすくなります。

ただし、検索が間違えば誤った資料を渡しますし、資料中のプロンプトインジェクションもありえます。RAGは、知識と出典の問題を改善しますが、完全な事実保証ではありません。

# [14: Slide 72/98] 公平性：バイアスの対策

バイアスへの対策では、[公平性](fairness)を評価目標として明示します。

「どの個人や集団も、不当な差別を受けないように扱うべきだ」という規範を、測定可能な指標へ落とします。人種、ジェンダー、国籍など、差別から保護したい属性を[保護属性](protected attributes)として定めます。

そして、全体の正答率だけでモデルを選ぶのではなく、保護属性ごとの誤りや結果の配分も評価します。

重要なのは、公平性はデータから自動的に決まる性質ではないことです。何を不当と考え、どの集団を守り、どの差を許容しないかを先に決める必要があります。

# [14: Slide 73/98] 集団レベルの公平性の基準は多数ある

集団レベルの公平性には、複数の定義があります。

デモグラフィック・パリティは、保護属性にかかわらず、肯定的な判定が同じ割合になることを求めます。これは結果配分の平等です。

均等化オッズは、実際の正解が同じ人同士で、予測の当たり方と外し方が集団間で同じになることを求めます。COMPASの偽陽性率の差は、この観点で問題になります。

予測的パリティは、同じ予測を受けた人について、その予測の信頼性が集団間で同じであることを求めます。

これらは同時に満たせないことが多く、どの公平性を採用するかは応用の目的、損害の性質、社会的な合意に応じて設計しなければなりません。

# [14: Slide 74/98] 基本的な対策は、一般的なサイバーセキュリティと何も変わらない

このセクションをまとめます。

ユーザー側は、AIの限界を知り、機密情報を守り、重要な出力を検証し、リテラシーを持って自己防衛します。サービス提供側は、リスクを明示し、権限を制限し、モニタリングを行い、最新の脅威情報に基づいて対策を更新します。

AIには、学習データのバイアスを引き継ぐ、挙動を完全には保証できない、自然言語で自由に操作できる、といった固有の事情があります。そのため、アラインメント、RAG、公平性評価などの技術も組み合わせます。

ただし、基本は変わりません。単一の対策へ依存せず、多層の防御と責任ある運用を行うことです。

# [14: Slide 75/98] もっと学ぶための資料案内：AISI

さらに学びたい人は、まず日本のAISIが公開しているガイドを見てください。

特に「AIセーフティに関する評価観点ガイド」は、経営、開発、評価の各立場で何を確認すべきかを体系的に整理しています。

AI安全の分野は変化が速いので、教科書を一冊覚えるより、こうした更新される公式資料を定期的に確認する方が実務的です。

# [14: Slide 76/98] もっと学ぶための資料案内：セキュリティ分類とフレームワーク

英語の資料では、NISTの敵対的機械学習の分類、Robust IntelligenceのAIセキュリティ分類と参考アーキテクチャ、DatabricksのAI Security Frameworkなどがあります。

こうした資料の価値は、個別の攻撃名を覚えることより、自分たちのシステムを、データ、モデル、アプリケーション、権限、監視という層に分けて点検できることです。

実際にサービスを作るときは、1つのガイドだけを正解とせず、複数の枠組みを照合し、自社の利用場面に合わせてリスク台帳と評価項目を作るとよいでしょう。

# [14: Slide 78/98] 著作権や特許権が議論の的。関連法規の整備も進む

AIと知的財産の関係を大づかみに言うと、著作権は創作的な「表現」を守り、特許権は一定の要件を満たした技術的な「アイデア」を守ります。

AI開発では、学習データ、ソースコード、学習済みモデル、生成物について、誰にどの権利があるかが問題になります。

ほかにも、営業秘密、限定提供データ、個人情報、労働法、競争法など多くの論点がありますが、今日は著作権と特許を中心にします。さらに、AIそのものに関する各国の制度整備も進んでいます。

# [14: Slide 79/98] AI開発では、よく著作権が問題になる

著作権は、著作物に対する一定の独占的な権利です。

著作物は、「思想または感情を創作的に表現したもの」で、文芸、学術、美術、音楽などの範囲に属するものと定義されます。単なる事実やアイデアではなく、人間の創作的な表現が保護されます。

財産権としては、複製、公衆送信、譲渡などをコントロールする権利があります。加えて、著作者人格権として、公表するか、氏名をどう表示するか、勝手に改変されないかを守る権利があります。

AI開発では、学習のためにコピーする行為、モデルやデータを配布する行為、生成物を公開する行為が、それぞれ問題になります。

# [14: Slide 80/98] データには著作権が発生したりしなかったりする

データだから一律に著作権がある、あるいはない、とは言えません。

年齢、性別、購買履歴、測定値のような客観的事実には、通常、それ自体の著作権はありません。表形式データの多くはこのタイプです。ただし、データベースの選択や配列に創作性があれば、データベース著作物として保護される場合があります。

人間が撮影した写真や、人間が書いた文章には、通常、創作性があれば著作権が生じます。一方、完全に自動撮影・自動生成されたものは、人間の創作ではないため、原則として著作物になりません。

学習データを扱うときは、ファイル形式ではなく、中身が何で、誰がどのように作ったかを確認する必要があります。

# [14: Slide 81/98] 日本では、AI開発のためのデータ利用は原則として著作権侵害にならない

日本の著作権法には、AI開発と関係の深い特徴的な規定があります。第30条の4です。

この条文は、著作物に表現された思想や感情を人間が鑑賞する目的ではなく、情報解析などのために利用する場合、一定の範囲で著作物を利用できると定めています。

機械学習では、文章を読んで内容を楽しむのではなく、大量のデータから言語的な特徴や統計的な規則性を抽出します。そのため、原則としてこの規定の対象になりうる、という整理です。

ただし、「原則として」です。著作権者の利益を不当に害する場合には適用されないという但し書きがあります。何をしても自由、という規定ではありません。

# [14: Slide 82/98] 文化庁のQ&AでもAI学習が具体例として示されている

これは、AI企業が都合よく条文を解釈しているという話ではありません。

文化庁のQ&Aでは、人工知能の開発のために著作物を学習用データとして収集・利用する行為や、その目的で第三者へ提供する行為が、具体例として挙げられています。プログラムを調査・解析するリバースエンジニアリングも例に含まれます。

つまり、情報解析を促進する意図を持って導入された制度です。一方で、特定の作品を再現するための利用や、既存のデータベース市場を代替するような利用など、権利者の利益を不当に害する場合は別問題です。

日本は、AI学習に比較的広い余地を認める制度設計をしている、と理解してください。

# [14: Slide 83/98] プログラムやソフトウェアに対する著作権は発生する？

プログラムは、人間が創作的に書いた表現なので、著作物として保護されます。ソースコードを無断でコピーし、配布すれば、著作権侵害になりえます。

一方で、コードが実現しているアルゴリズム、数学的手法、処理のアイデアそのものは、著作権では保護されません。同じアイデアを、独自のコードで実装することは原則として可能です。

著作権が守るのは表現であって、問題の解き方そのものではない、という区別です。アルゴリズムを排他的に保護したい場合には、次に出てくる特許が関係します。

# [14: Slide 84/98] 学習済みモデルに対しては？

では、学習済みモデルのパラメーターには著作権があるでしょうか。

通常、パラメーターは最適化計算の結果として得られた大量の数値です。人間が一つ一つ創作的に表現したものではないため、原則としてパラメーター自体には著作権が生じないと考えられます。

ただし、モデルの配布には契約やライセンスを設定できますし、モデルの構成、付属コード、文書、商標、営業秘密など、別の権利は存在します。「著作権がない」ことと「何の制約もなく使える」ことは同じではありません。

# [14: Slide 85/98] 生成AIの生成物に著作権は発生するか？

完全にAIだけが自動生成したものには、人間の創作的寄与がないため、原則として著作権は発生しません。

しかし、人間がAIを道具として使い、構図、表現、編集、選択を具体的に決めた場合には、人間の創作部分について著作権が認められる可能性があります。プロンプトにどれほど具体的な創作性があるかも、場合によって論点になります。

したがって、「AIを使ったら著作権がない」「プロンプトを書けば必ず著作権がある」という単純な二択ではありません。最終的な表現に、人間がどの程度創作的に関与したかを個別に見ます。

# [14: Slide 86/98] 生成AIの生成物が著作権侵害をすることはあるか？

自分の生成物に著作権が発生しない場合でも、他人の著作権を侵害することはありえます。

侵害の判断では、既存作品と創作的表現が似ているかという[類似性](similarity)と、その作品をもとに作ったといえるかという[依拠性](reliance)が主な論点になります。

生成AIの場合、利用者が元作品を指定していなくても、モデルが学習時にその作品を見ていた可能性があります。学習したという事実だけで依拠性が成立するのか、モデル内部にどの程度表現が残っているのかは、現在も議論が続いています。

実務では、特定作家や既存キャラクターを明示して生成する、元画像を強く参照させる、といった利用ほどリスクが高くなります。

# [14: Slide 87/98] AIの研究開発の成果である発明を、特許で保護したい場合がある

次は特許です。

日本で特許を受けるには、自然法則を利用した技術的思想であり、産業上利用でき、新規性と進歩性があり、内容が明確で、実施できるように説明されている必要があります。

日本は先願主義なので、同じ発明なら先に出願した人が原則として特許を得ます。研究や事業で重要な技術を作った場合、公開する前に出願すべきか、営業秘密として守るかを検討します。

特許は、発明を公開する代わりに、一定期間の独占権を与える制度です。

# [14: Slide 88/98] AIの研究開発の成果物は、ソフトウェアの形をとることが多い

AIの新しい学習方法や、新しい応用方法は、ソフトウェアとして実装されることが多いです。

単なる数学的アルゴリズムだけでは特許になりにくい一方、CPU、メモリー、ストレージ、入出力装置を使って、どのような情報処理を実現するかを具体的に記載すれば、ソフトウェア関連発明として認められることがあります。

つまり、「ニューラルネットを使う」と抽象的に書くだけでは足りません。入力をどう処理し、何を出力し、ハードウェア上でどのような技術的効果を生むかを、明細書と図面で説明する必要があります。

# [14: Slide 89/98] 研究成果は公表したいが、公開すると新規性が失われる

研究者には、特許とは別の事情があります。論文や国際学会で公表して初めて、研究成果として評価されるからです。

しかし、出願前に論文を公開すると、自分の発明であっても新規性を失うのが原則です。そこで特許法第30条には、一定の場合、公開から1年以内に出願すれば新規性喪失の例外を受けられる制度があります。

ただし、これは安全な「1年間の猶予」ではありません。公開を見た第三者が先に出願することを防げず、外国では同じ例外が使えない場合もあります。

企業や大学で研究する場合、論文投稿の前に知財部門へ相談し、出願と公表の順番を調整することが大切です。

# [14: Slide 90/98] 日本では2025年6月4日にAI法が公布・施行された

日本では、「人工知能関連技術の研究開発及び活用の推進に関する法律」、いわゆるAI法が施行されています。

主な内容は、国としてAI基本計画を策定することと、内閣にAI戦略本部を置くことです。本部長は内閣総理大臣で、全閣僚が参加します。

この法律は、多くの企業行動を直接禁止し、罰金を科す規制法というより、国や地方公共団体の施策を方向づける基本法・理念法の性格が強いです。安全保障、研究開発、国際競争力の強化など、AIを推進する方向に力点があります。

一方、協力しない事業者が国の指導や助言の対象になる可能性もあり、今後の政策の土台になります。

# [14: Slide 91/98] 背景には、ソフトローからハードローへの変化がある

従来は、「EUは法律で強く規制し、日本や米国はガイドライン中心」という対比で説明されることが多くありました。

日本ではAI事業者ガイドラインのような、法的拘束力のないソフトローを中心に、技術の変化へ柔軟に対応する方針が取られてきました。ところが、生成AIが安全保障、選挙、雇用、消費者保護へ広がる中で、米国も大統領令などによる強い介入を始め、日本でも法律を持つべきだという議論が進みました。

AI法は、EUのAI Actのように用途ごとの禁止や厳しい適合義務を並べる制度ではありません。しかし、日本もソフトローだけに依存せず、法律とガイドラインを組み合わせる段階へ入ったと見ることができます。

# [14: Slide 92/98] 人工知能基本計画が策定されている

AI法に基づいて、内閣府は人工知能基本計画を策定し、その後も更新しています。

法律は大きな方向を定めるだけなので、研究開発、人材育成、計算資源、安全性、行政利用、国際連携などの具体的な政策は、この基本計画で示されます。

スライドにリンクを載せています。政策資料は抽象的に見えますが、どの分野へ予算が付き、政府が何を課題と認識しているかを知る一次資料です。時間があれば、項目を眺めてみてください。

# [14: Slide 93/98] AIを実現する技術そのものが、市場で流通する財になっている

最後に、AI関連市場を見ます。

AIは企業が内部で使う道具であるだけでなく、モデル、API、クラウド計算、GPU、データセンターといった技術そのものが商品として売買されています。

生成AIサービスへ利用料を払う市場があり、その背後にはモデルを訓練する企業、計算資源を貸すクラウド企業、半導体と電力設備を供給する企業があります。

AIの産業構造を見るときは、最終的なアプリだけでなく、その下のモデル層、クラウド層、半導体・インフラ層まで見る必要があります。

# [14: Slide 94/98] ChatGPTは2か月で1億人の月間アクティブユーザーを達成

ChatGPTは、公開から約2か月で月間アクティブユーザー1億人に達したと推定され、当時の消費者向けアプリとして非常に速い普及でした。

Instagramが同規模へ達するまで約2年半、TikTokでも約9か月かかったとされます。対話するだけで価値を体験でき、既存のパソコンやスマートフォンから利用できたため、導入の摩擦が極端に小さかったことが背景にあります。

この普及を受け、生成AIは、個人向け定額サービス、企業向けSaaS、API、広告、クラウド計算まで含む大市場になりました。ただし、市場予測の数字は仮定に大きく依存するので、規模感として見るのがよいです。

# [14: Slide 95/98] モデルを作るプレイヤーは少数・寡占な状況

一方、最先端の大規模モデルをゼロから作れる企業は限られています。

LLMの基本技術は論文やオープンソースで広く共有され、人材も企業間を移動するため、1社だけが技術を独占する状況にはなりませんでした。しかし、最先端モデルの学習には、データ、研究者、GPU、電力を含めて100億円規模以上の投資が必要になります。

その投資を回収できる見込みがあり、大規模な計算資源を調達できる企業しか参入できません。技術知識は比較的開かれていても、資本と計算資源が参入障壁になります。

# [14: Slide 96/98] 深層学習時代の最重要な計算資源はGPU

その計算資源の中心が[GPU](ジーピーユー)です。

GPUはもともと画像表示のためのハードウェアですが、同じ種類の計算を大量に並列実行するのが得意です。ニューラルネットの学習では、全結合層、畳み込み、注意機構、誤差逆伝播の多くが大規模な行列演算として表されます。

そのため、CPUだけで計算するより、数十倍から100倍以上速くなる場合があります。1か月と100か月の差になれば、単なる便利さではなく、モデルを作れるかどうかを決める差です。

この「GPUによる汎用計算」をGPGPUと呼びます。

# [14: Slide 97/98] その結果、半導体業界に投資が集まっている

GPU需要の拡大によって、NVIDIAを中心に半導体、メモリー、ネットワーク、データセンター、電力設備へ資金が集まっています。

NVIDIAはGPUだけでなく、CUDAという開発環境を長年整備し、研究者と企業が使いやすいソフトウェアの生態系を作りました。ハードウェアの性能だけでなく、周囲のソフトウェアと人材の蓄積が競争力になっています。

モデル開発企業は、10万台規模の高性能GPUクラスターを建設し、GPUの調達自体で競争しています。AI市場では、モデルのアイデアだけでなく、半導体、ネットワーク、冷却、電力、土地を確保できるかが事業上の制約になります。
